# Sparkshield Stowage Fire-Risk Planner
**NASA Space Apps Challenge 2026 · Flame in Freefall** · Team GitPushToTheMoon (Seattle)

🔗 Live demo: https://flame-api-32147745125.us-west1.run.app

Turning NASA's microgravity fire experiments into stowage decisions crews can act on.

## Mission

Fire behaves differently in space, and the data on how materials burn in microgravity sits in
NASA's experiment archives. Our mission is to put that data to work: we help mission planners and
crews see which stowed items raise fire risk, why, and what to move, with every score tied to
real NASA tests.

## What it does

- **Stowage planner:** lay out a spacecraft (ISS-style station, transit spacecraft or a custom
  hull), stow items in each module, and get a fire-risk score for every module and the whole ship
  across two mission phases: in-space cruise and a Moon or Mars surface stay.
- **Fixes and moves:** the app tests every swap, detector, extinguisher and item move, re-scores
  the ship, and suggests only the changes that actually lower the risk.
- **Engineer and crew modes:** engineers can add, move and delete modules within a fixed hull;
  the crew handoff mode locks the layout so only items can change.
- **Fire-safety agent:** plain-language explanations and a chat that answers questions using
  our NASA dataset, with citations to the specific experiments.
- **Experiment library:** a ranked, AI-summarized library of 339 NASA combustion tests.

All scores are computed in code from NASA data. AI only writes the explanations, and its text is
checked against the data before it is shown.

## Setup (once)

Requires **Python 3.9+**.

```
git clone https://github.com/GitPushToTheMoon/SpaceApps2026.git
cd SpaceApps2026
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # then fill in the values below
```

### `.env` settings
`.env` is git-ignored. Never commit it. Get the API key from a teammate privately.

| Setting | Required | What it does |
|---|---|---|
| `GEMINI_API_KEY` | yes (unless Vertex) | Key from aistudio.google.com |
| `GEMINI_MODEL` | yes | Main model, e.g. `gemini-3.5-flash-lite` |
| `GEMINI_FALLBACK_MODEL` | recommended | Used automatically if the main model is overloaded, e.g. `gemini-3.1-flash-lite` |
| `GEMINI_THINKING_LEVEL` / `GEMINI_THINKING_BUDGET` | no | Limit "thinking" for faster answers if you get 504 timeouts |
| `USE_VERTEX` | no | `true` = use Vertex AI (Google Cloud credits) instead of the AI Studio key; also set `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION`, `GOOGLE_APPLICATION_CREDENTIALS` |
| `FRONTEND_ORIGIN` | no | Which frontend URLs may call the API; `*` = any, or comma-separated URLs |
| `ADMIN_TOKEN` | no | Protects `POST /admin/reload` when deployed (send as `X-Admin-Token`) |

List the model names your key can use:
```
python -W ignore -c "from dotenv import load_dotenv; load_dotenv(); import os; from google import genai; c=genai.Client(api_key=os.environ['GEMINI_API_KEY']); [print(m.name) for m in c.models.list() if 'flash' in m.name]"
```

## Run

Every new terminal: `cd SpaceApps2026 && source .venv/bin/activate`

```
uvicorn backend.main:app --reload --host 0.0.0.0
```
- API: http://localhost:8000
- Interactive docs: http://localhost:8000/docs (click an endpoint → **Try it out** → **Execute**)
- Stop with Ctrl+C. `--reload` restarts automatically when you save a file.

Everything except `POST /assess` works without Gemini.

## How `POST /assess` works

The AI never decides the evidence, the risk level, or any numbers.

1. **Match** (`matching.py`): scores every verified experiment by distance from the user's
   oxygen, pressure and airflow, with a penalty for a different material. Returns the 5 closest.
2. **Data gaps** (`matching.py`): computed in code, e.g. "No closely matching tests at 34% oxygen",
   "No partial-gravity combustion data yet".
3. **Risk level** (`risk.py`), rules checked in order ("about the same" = within 1% oxygen):
   - **high**: the same material burned at the user's oxygen or lower
   - **low**: the same material only went out / didn't ignite at the user's oxygen or higher
     (never "low" when no material is chosen)
   - **elevated**: mixed results, or it only burned at higher oxygen
   - **insufficient data**: none of the closest tests used that material
4. **Evidence** (`risk.py`): one sentence per match, written from the CSV values.
5. **Explanation** (`ai.py`): Gemini writes 3–4 plain-English sentences from the facts above.
   Every number in it is checked against the real values; if one is wrong it retries once,
   then falls back to a code-written explanation.

Identical requests are cached (no extra Gemini calls). If Gemini is down after retries and the
backup model, `/assess` returns **502** "AI assessment unavailable"; everything else keeps working.

## How `POST /api/assess` works (stowage planner)
1. **Adapter** (`adapter.py`) turns the planner JSON into scoring input; library keys link
   items to the NASA test data (`data/library.json` → `material_key`).
2. **Scores** (`scoring.py`): each material's hazard comes from the burn/no-burn tests at that
   phase's oxygen (untested items use their Low/Moderate/High level). Each room combines
   hazard, fuel load, ignition and oxygen sources (its own and its neighbours'), airflow and
   thickness, minus credit for detectors and extinguishers. Ship and overall scores are
   weighted from the rooms and phases.
3. **Fixes and moves** (`actions.py`): code tries each swap, detector, extinguisher and move,
   re-scores the ship, and keeps only changes that lower the score, with the real points.
4. **Text** (`ai.py`): Gemini writes the summary, rationales and fix reasons from those facts.
   Any wrong number sends it back once, then template text is used. Always returns 200.
5. **Chat** (`POST /api/chat`): Gemini answers about one tab; its actions are checked and
   re-scored by code. Returns 503 when Gemini is down.

## Data

- **experiments.csv**: 339 rows from PSI: FLEX droplets (274), BASS-II (24), Saffire I–III (14),
  ACME BRE (18), ACME s-Flame (9). Only rows with `verified = yes` are served.
  `outcome_category` is one of: burned, self-extinguished, blowoff, no ignition, no spread,
  ignited, other, unknown.
- **materials.csv**: `material` values in experiments.csv must match these names exactly.

  | material | plain English | type | tests |
  |---|---|---|---|
  | PMMA | acrylic plastic | solid | 27 |
  | SIBAL fabric | cotton/fiberglass cloth | solid | 6 |
  | silicone | silicone sheet | solid | 4 |
  | Nomex | fire-resistant fabric | solid | 1 |
  | cotton fabric / Ultem / wax-fiberglass | | solid | 0 |
  | methanol | liquid fuel droplet | liquid | 157 |
  | heptane | liquid fuel droplet | liquid | 117 |
  | heptane-isooctane | 50/50 fuel mix | liquid | 0 |
  | ethylene / methane | gas fuels | gas | 22 / 5 |

- **presets.json** (used by `POST /assess`): ISS cabin (14.7 psi, 21% O2, 0 g), Moon habitat
  (8.2 psi, 34%, 0.166 g), Mars habitat (8.2 psi, 34%, 0.38 g). Temperature is display-only
  (no experiment recorded it).
- **Stowage planner surface atmospheres**: Sea-level (14.7 psia, 21% O2), Moon base
  (10.2 psia, 26.5% O2, the default) and Exploration (8.2 psia, 34% O2). Cruise is always
  14.7 psia, 21% O2, 0 g.
- Numbers come from the source documents, never from the AI.

### Regenerating AI summaries (`analysis.json`)
Only needed if experiments.csv changes or you change the prompt. It is already committed.
```
python -W ignore -m backend.analyze --limit 5        # test a few, read data/analysis.json
python -W ignore -m backend.analyze                  # all remaining (~10–15 min)
python -W ignore -m backend.analyze --redo           # redo everything
python -W ignore -m backend.analyze --ids PSI-69-019 # specific experiments
python -W ignore -m backend.analyze --fix-environments  # re-apply habitat rules, no AI calls
```
Saves after every experiment; safe to stop and re-run (skipped ones are retried).
Then `POST /admin/reload` (or restart the server).

## Troubleshooting

| Problem | Fix |
|---|---|
| `python: command not found` / `ModuleNotFoundError` | Activate the venv: `source .venv/bin/activate` |
| `Address already in use` | Server already running. Use it, or stop it: `pkill -f "uvicorn backend.main:app"` |
| `503 UNAVAILABLE` / `504 DEADLINE_EXCEEDED` | Gemini overloaded: switch `GEMINI_MODEL` to a Lite model, set `GEMINI_FALLBACK_MODEL`, or use Vertex |
| `403 PERMISSION_DENIED` (SERVICE_DISABLED) | Enable "Generative Language API" in Google Cloud for that project |
| `403` (API_KEY_SERVICE_BLOCKED) | Key restrictions: allow "Generative Language API" on the key |
| 422 in `/docs` | Real errors appear under **Server response**; the Responses section below it is just reference. `loc` names the bad field |
| `/assess` returns an old answer | Answers are cached: `POST /admin/reload` |
| Python 3.9 `FutureWarning`s | Harmless; add `-W ignore` |
| On Python 3.9 | Write `Optional[str]`, not `str \| None` |

## Deploy (Google Cloud Run)
Build the frontend first (the backend serves `frontend/dist`), then deploy from the repo root:
```
cd frontend && npm install && npm run build && cd ..
gcloud run deploy flame-api --source . --region us-west1 --allow-unauthenticated \
  --set-secrets GEMINI_API_KEY=gemini-api-key:latest \
  --set-env-vars GEMINI_MODEL=gemini-3.5-flash-lite,GEMINI_FALLBACK_MODEL=gemini-3.1-flash-lite,FRONTEND_ORIGIN=* \
  --min-instances 1
```
The Gemini key is stored in Google Secret Manager (`gemini-api-key`), never in code or in the
command. The `Procfile` provides the start command.

- PSI-25 Burning and Suppression of Solids – II (BASS-II), 24 tests: https://psi.nasa.gov/physci/repo/data/investigations/PSI-25

- PSI-99 Spacecraft Fire Experiment-II (Saffire-II), 10 tests: https://psi.nasa.gov/physci/repo/data/investigations/PSI-99
- PSI-23 ACME – Structure and Response of Spherical Diffusion Flames, 9 tests: https://psi.nasa.gov/physci/repo/data/investigations/PSI-23
- PSI-98 Spacecraft Fire Safety Experiment-I (Saffire-I), 2 tests: https://psi.nasa.gov/physci/repo/data/investigations/PSI-98

**Mission atmosphere and gravity presets:**
- ISS cabin atmosphere: NASA Technical Report 20120015343, Table 1. https://ntrs.nasa.gov/api/citations/20120015343/downloads/20120015343.pdf
- Moon and Mars habitat atmosphere: NASA Exploration EVA Concept of Operations. https://www.nasa.gov/wp-content/uploads/2020/01/topic_1-_eva_lunar_surface_concept_of_operations.pdf

Google Gemini API; Google Cloud Run and Secret Manager.

This tool is a research aid, not a safety certification.

## AI Disclosure

This project uses AI in two ways:

- **In the app:** Google Gemini (`gemini-3.5-flash-lite`, fallback `gemini-3.1-flash-lite`) writes the
  plain-language explanations and chat answers. All risk scores are computed by our own code from
  NASA PSI data, not by AI. Before any AI text is shown, it is checked against the data (numbers,
  experiment IDs, citations and unscored causes); if a check fails, the app shows template text instead.
- **In development:** parts of the backend and frontend code, tests and documentation were written
  with help from Anthropic's Claude. Our team made the design and technical decisions and reviewed
  and tested all code.

No AI-generated images, video or audio are used, and no NASA branding appears in generated content.
